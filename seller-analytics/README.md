# Маржа · локальная версия 0.1

Первая рабочая сборка для разработки аналитики одного кабинета WB и четырёх кабинетов Ozon. Это локальный прототип, не готовая замена TrueStats.

## Запуск

Python 3.9+; внешние зависимости не нужны. На этом Mac можно открыть `Start.command` двойным щелчком в Finder. Или в терминале из этой папки:

```sh
SELLER_PORT=8941 python3 -B server.py
```

Открыть http://127.0.0.1:8941. Остановка — Ctrl+C. Порт можно изменить через SELLER_PORT. Привязка только к 127.0.0.1. Не открывайте сервер в интернет и не используйте обратный прокси: авторизации пока нет.

Данные хранятся в `.runtime/analytics.sqlite3` внутри папки проекта. Демонстрационный набор и ручные записи владельца разделены по `tenant`. Это техническая основа, не реализованная система прав SaaS. Повторный запуск обновляет синтетические операции, не удаляя ручные записи.

## Что работает

- Демо сентября 2026: 5 условных кабинетов, 8 товаров, операции и рекламные примеры.
- Фильтры по периоду и кабинету, поиск товара.
- Финансовая сводка и детализация до исходных операций; экспорт полного реестра в CSV.
- Ручной ввод расходов с сохранением на компьютере.
- Импорт истории себестоимости из CSV, строгая проверка всех строк перед сохранением.
- Расчёты в копейках, защита от повторного импорта одной операции.
- Отдельный пустой режим «Мои данные»; без подстановки демо вместо отсутствующих продаж.

Себестоимость из CSV хранится, но ещё не участвует в расчёте демонстрационных продаж. Демо содержит собственные синтетические проводки себестоимости. Автоматическая связь стоимости с реальными продажами — следующий этап.

## Что пока не реализовано

WB/Ozon API, защищённое хранилище ключей, Google Sheets/Диск/почта, Telegram, налоговый расчёт, производство и комплекты, валютный учёт, остатки, закупки, ДДС, ROI на капитал, управление рекламой, авторизация и роли, промышленное резервное копирование.

Не вводите API-ключи в описание расходов или CSV. В этой версии нет формы хранения секретов.

## Проверки

```sh
python3 -B -m unittest discover -s tests -v
```

API-тесты поднимают временный сервер на loopback и отдельную временную базу. Финансовые тесты проверяют возвраты, датированную себестоимость, неполные данные, округление, дубли, корректировки, изоляцию режимов. Они не подтверждают соответствие реальным отчётам маркетплейсов: для этого нужны ваши источники.

## Файлы

- `server.py`: локальный HTTP API, импорт и экспорт.
- `engine.py`: правила суммирования и вспомогательные расчёты.
- `store.py`: хранение операций, стоимости и журнала изменений.
- `demo.py`: воспроизводимые вымышленные данные.
- `static/`: адаптивный интерфейс без внешних CDN и трекеров.
- `docs/SPEC.md`: согласованные вводные и следующие этапы.

В текущей сборке новые финансовые операции неизвестного типа нельзя молча включать в прибыль: их сначала нужно классифицировать. В будущих загрузчиках они должны попадать в очередь разбора.
