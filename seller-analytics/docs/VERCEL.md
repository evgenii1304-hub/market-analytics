# Публикация демоверсии «Маржи» на Vercel

Репозиторий: evgenii1304-hub/market-analytics, ветка main.
Приложение находится в seller-analytics; корневой index.html репозитория — предыдущая страница.

## Настройки существующего проекта

1. Откройте проект Vercel, связанный с этим репозиторием.
2. Settings → Build and Deployment → Root Directory: `seller-analytics`. Сохраните.
3. Framework Preset: `Other`.
4. Build Command: `python3 -B build_preview.py`.
5. Output Directory: `dist`.
6. Install Command: пустой. Переменные окружения не требуются.
7. Settings → Git: проверьте репозиторий и Production Branch `main`.
8. Deployments → последний деплой main → Redeploy. После статуса Ready откройте домен проекта.

Команды и выходная папка также заданы в seller-analytics/vercel.json.
При создании отдельного проекта используйте Add New → Project, импортируйте тот же репозиторий и задайте те же параметры.

## Что работает

Публичная статическая демоверсия: обзор, товары, реклама, финансы, фильтрация по кабинету и датам, экспорт CSV. Все записи вымышлены. При сборке создаётся новая временная база из demo.py; локальная .runtime/analytics.sqlite3 не читается. В публикацию попадают только index.html, app.js, style.css, preview.js и preview-data.json.

Ввод расходов, импорт себестоимости, API и реальные данные не публикуются. Локальное приложение продолжает работать через Start.command. Для полноценного сервиса потребуется защищённый сервер и постоянная база в России. Локальный файл SQLite не является постоянным хранилищем для Vercel Functions.

## Проверка после публикации

Откройте главную страницу, переключите кабинет и период, проверьте разделы и скачивание CSV. Над аналитикой должно быть указано «Демоверсия “Маржи”». «Мои данные» недоступны; в разделе расходов нет формы отправки. В Network не должно быть обращений к /api/state или ошибок 404 при загрузке данных.

Документация: https://vercel.com/docs/monorepos и https://vercel.com/kb/guide/is-sqlite-supported-in-vercel.
